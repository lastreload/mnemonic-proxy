How it works

An OpenAI / Anthropic / Responses-compatible HTTP proxy. Your agent talks to it exactly as it would talk to the model. No summaries written by a model, no vector database required.

01 · HIDE

Mask, don't summarize

Old tool outputs and reasoning leave the prompt in stable blocks and become one-line receipts with an id. The prefix stays byte-identical between blocks, so the engine's KV cache keeps working.

02 · RECALL

Structured, exact recall

A recall tool searches the verbatim archive: first write of a file, its full edit timeline, command → output, the reasoning behind an edit — every hit tagged with message number and segment.

03 · SEGMENT

Segments with handoff notes

When even the masked window fills up, the model writes its own notes, the segment is sealed and a fresh one starts. Pinned lines (!!) survive every switch.

04 · SAVE

Saved engine state

On engines that support it (llama-server, Strata) the KV state is saved to disk: resuming after a pause, a restart or another client takes 1–3 s instead of a full re-read.

05 · ARCHIVE

Deduplicated cold storage

Old state files are rebuilt bit-for-bit from content-addressed zstd blocks: −36% disk on our sessions, sha256-verified before every restore.

06 · LEAN

Tools on demand

Agents ship tens of thousands of tokens of tool definitions. The proxy keeps the core ones and loads the rest by name: 25.6K → 6.2K tokens on every request.

"In the courier business you don't read the payload. You carry it, and you give it back exactly as it was."— the design rule. Hidden content is never paraphrased; it is either in the prompt or retrievable verbatim.

Why it matters. Without saved state, the whole prefill of a long conversation is paid again every time the engine loses it — after a restart, when another client used the engine in between, when the proxy returns to a sealed segment. On a 12 GB GPU that is close to a minute for 100K tokens; restoring takes a second or two, from disk, not VRAM. Any client of a local engine benefits, not just this proxy. llama-server has it (--slot-save-path); for Strata it is proposed in PR #668, not yet merged.

Run it

Python ≥ 3.10, standard library only (optional: tokenizers for exact counts). Point it at any OpenAI-compatible engine; with llama-server you also get saved state.

# 1. an engine — llama.cpp with slot saving
$ llama-server -m model.gguf -c 131072 --slot-save-path ./slots --port 8095

# 2. the proxy
$ pip install git+https://github.com/lastreload/mnemonic-proxy
$ mnemonic-proxy --upstream http://127.0.0.1:8095 --port 8096 --data ./data

# 3. your agent → http://127.0.0.1:8096
$ OPENAI_BASE_URL=http://127.0.0.1:8096/v1 pi              # Chat Completions
$ ANTHROPIC_BASE_URL=http://127.0.0.1:8096 claude          # Anthropic Messages
$ codex -c model_providers.local.base_url=http://127.0.0.1:8096/v1 \

What we have not proven

  • Long-range quality is not free. Of six questions about the first hour of a 3-hour session, four were answered exactly, two partially (one value missed, one timeline mixed up). None were invented.
  • The model does not attend to 448K tokens. It sees at most one window; the rest is recallable, not "in context".
  • Segment switches cost ≈2 minutes of note-writing on a 12 GB GPU.
  • Saved state on Strata needs our session-files branch until PR #668 is reviewed; official Strata runs in base mode.
  • Claude Code and Codex are tested live only on Strata; on other engines only against mock engines.
  • Copied shortened arguments. Live, in 3 writes out of 140 the model copied the shortened form of an old tool argument into a file (one caused a real NameError). 0.3.0 blocks these writes; tested on a mock engine, not yet live.
  • Old reasoning is masked. Questions answered only in the model's reasoning: 3 exact + 1 partial of 5 with it, 2 of 5 without — and the model presented later values as the original ones instead of saying it did not know.
  • The archive is plaintext. It holds everything the agent saw, secrets included. The proxy binds to 127.0.0.1; protect the data folder.
